# 0075: The public website reads published content by address and stores visitor requests per organization

- Status: accepted
- Date: 2026-10-29

## Context

Prompt 81 ports Waypoint's journey 28 (Explore public site): `L2-PUB-001` to `L2-PUB-003`, as `L2-132` to `L2-134`. Waypoint is single-tenant: one public site, `GET /api/public/content` over every published track, every cohort with its neighbourhood and lead mentor, and three anonymous forms that store a contact request, a volunteer sign-up and a donation pledge with an opaque payment-provider reference. PromiseHub serves many organizations from one deployment, chooses the tenant from a membership everywhere else (`L2-001`), and has already decided that the public website is the Public website module, reached at `/site/{slug}` through `Organization.WebsiteSlug`, answering 404 for an unknown slug, a suspended organization or the module off (ADR 0043). A Waypoint cohort is a PromiseHub program, and applying is the program's enrollment link (prompt 58, ADR 0052).

## Decision

- **The address is the tenant.** `PublicSiteResolver` (`Application/Website/`) is the one place PromiseHub chooses a tenant without a membership. It finds the organization by its lower-cased address ignoring the tenant filter for that single lookup, refuses a suspended organization, then resolves the tenant for a visitor (`TenantContext.ResolveForVisitor`, actor "Website visitor") so every later query runs inside the ordinary tenant filter, and answers null unless that organization's Public website module is on. Every website endpoint goes through it, so every endpoint answers the same 404 in the same cases and nothing else in the request can name another organization.
- **Anonymous by explicit opt-in.** `WebsiteEndpoints` maps `GET /website/{slug}`, `GET /website/{slug}/content` and `POST /website/{slug}/contact`, `/volunteer` and `/donations`, each with `AllowAnonymous()`. They read no session and accept none.
- **Published content only, computed on read.** `GET /website/{slug}/content` answers active, not archived programs that have not ended (by the organization's UTC today), ordered by start date, with schedule, ages, dates, a status computed once (`Running` or `Upcoming`), the enrollment link's path while enrollment is open, the published track a program follows while Learning is on, and its lead mentor's first name while Mentoring is on. While Learning is on it adds published tracks with at least one published module, their published modules in order and each module's "module completed" badge. Impact counts are programs running, programs open, and while Learning is on published tracks and modules. No count of people, no capacity, no child, guardian or staff detail is ever answered. Waypoint's neighbourhoods have no PromiseHub field and are not ported.
- **The journey and promises are fixed copy.** The four steps on the home page and the promise to families on the about page are product copy in the frontend, not per-organization content; editing them is deferred.
- **Visitor requests are three tenant-owned tables.** `ContactMessage`, `VolunteerInterest` and `DonationPledge` (`Domain/Website/`) carry the organization id. `WebsiteRequestsHandler` validates on the server (lengths, email, the fixed topic, area and tier lists, the screening acknowledgement), stores plain text and audits each as Created with the actor "Website visitor". Angular escapes on output, so markup typed by a visitor is shown, never run; Waypoint's HTML-encoding before storage is not ported because it corrupts plain text for every other reader.
- **Rate limited per email, per kind, per organization.** A sixth request of the same kind from the same email to the same organization within an hour answers 429 `too-many` and stores nothing. The limit is counted from the stored rows, so it needs no extra state and works across server instances.
- **Payments behind an abstraction.** `IPaymentProvider.StartCheckoutAsync` answers a hosted checkout (`PaymentCheckout(Reference, Url)`) or null when the organization has no provider. Infrastructure registers `UnconfiguredPaymentProvider`, which answers null, so a deployment without credentials says "Online giving isn’t available yet" (503 `unavailable`) and stores nothing. Tests and the fake API use a fake provider. The pledge stores the amount, name, email and the provider's reference only; card details never reach PromiseHub. Recurring monthly tiers of $20, $50 and $100 follow Waypoint's decision 13.
- **Frontend.** The `website` library loads at `/site/:slug` only when `websiteOn` sees the site load. `SiteLayout` reads the profile and the content once into `SiteState` and frames every page with the new `ph-site-nav` and `ph-site-footer` components. Contact is a dedicated screen whose content is the form; volunteering and giving open CDK dialogs from Get involved.
- **Deferred.** A staff inbox for contact messages, volunteer offers and pledges (they are in the database and the audit log until then); notifying staff of a new request; a real payment provider and its webhook confirming a payment; per-organization editing of the steps, promises and privacy text; one-time gifts and other amounts; a sitemap and server-side rendering for search engines.

## Consequences

- `TenantContext` gains `ResolveForVisitor`. `PublicWebsiteHandler` uses the resolver; `ParticipantModuleEndpoints` no longer maps the website endpoint.
- A migration adds `ContactMessages`, `VolunteerInterests` and `DonationPledges`, each with the organization id and the tenant filter.
- The fake API in `e2e/fixtures/fake-website.ts` answers the same content, requests and outcomes from its seeded programs, curriculum and mentor teams.
- Turning Public website off hides the pages and the endpoints; stored requests are kept.
