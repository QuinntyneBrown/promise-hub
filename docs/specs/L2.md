# L2 - Detailed Requirements

Each L2 traces to exactly one L1 in `L1.md`. Acceptance criteria are Given/When/Then and are the source for acceptance tests, which must carry a `Traces to: L2-nnn` header comment. Screen ids in parentheses refer to `docs/mocks/`. The cast (Harbourview Youth Collective, Jaylen, Marisol, Tom, the Rivera household) is the shared test fixture.

---

## L2-001: Tenant isolation on every query
**Traces to:** L1-001

Every tenant-owned table carries the organization id; every query, search, export and background job filters by the organization of the signed-in person's active membership, never by a value from the client.

**Acceptance Criteria:**
1. Given two organizations each with a child named "Mateo Rivera", when a staff member of organization A searches "Mateo", then only organization A's child is returned.
2. Given a staff member of organization A, when they request `/children/{id}` for a child of organization B by id, then the API answers 404 and the attempt is written to the audit log.
3. Given a request that carries an organization id in the body or query that differs from the active membership, when it is processed, then the server ignores the client value and uses the membership's organization.
4. Given the seeded demo data, when the integration suite runs, then every feature's cross-tenant test (one per feature) passes.

## L2-002: Active organization and switching
**Traces to:** L1-001

A person can belong to several organizations with a different role in each. One organization is active per session; switching reloads the app for the chosen organization.

**Acceptance Criteria:**
1. Given Priya belongs to Harbourview (admin) and Bayfront (volunteer coordinator), when she signs in, then the top bar shows the org switcher with Harbourview active (`switch-organization`).
2. Given the switcher is open, when she picks Bayfront, then Today reloads with Bayfront's data and her role there, and the active organization is explicit in every subsequent request.
3. Given a person belongs to one organization, when they sign in, then no switcher is shown.
4. Given a person's membership in an organization is removed while they are active in it, when they make the next request, then they are signed out of that organization and returned to their remaining organization or the sign-in page.
5. Given Priya switches with `POST /me/organization`, then only one of her own current memberships is accepted (another person's answers 404), the session cookie moves to it, the switch is audited in the organization joined, and `GET /me/organizations` lists her memberships with the active one marked.

## L2-003: Platform administration of organizations
**Traces to:** L1-001

Platform admins list, add, suspend and reinstate organizations; this list is the only screen that spans tenants.

**Acceptance Criteria:**
1. Given a platform admin, when they open `organizations`, then every organization is listed with plan, active children, modules on and status, filterable by plan and status and searchable by name.
2. Given a platform admin adds an organization with a name, a first admin email, a plan and a module preset (`add-organization`), when the form is submitted, then the tenant is created, the admin receives the welcome email and the row shows "Setting up".

4. Given an organization admin who is not a platform admin, when they open `/admin/organizations`, then they get the forbidden state and the API answers 403.

## L2-004: Module configuration per organization
**Traces to:** L1-002

Admins switch modules on or off in `settings-modules` or choose a preset during onboarding (`onboard-modules`). Roster is the data every other module reads; dependencies are declared and enforced.

**Acceptance Criteria:**
1. Given the whole suite is on, when the admin turns off every module except Roll Call and saves, then the configuration is stored with Roster and Roll Call on and the toast confirms 2 modules on.
2. Given Roll Call is off, when the admin turns Pickup on and saves, then the save is rejected with the inline error "Pickup needs Roll Call" and the API answers 422 naming the missing dependency.
3. Given Slips is on, when the admin turns Roster off, then the save is rejected naming every module that needs the roster.
4. Given the admin chooses the "Just check-in" preset in onboarding, when the wizard continues, then Roster, Roll Call and Quick Cards are on and everything else is off.
5. Given a site lead, when they open `/settings/modules`, then they get the forbidden state and the API answers 403.
6. Given Harbourview, when Settings › Modules opens, then Learning, Mentoring and Public website are listed after Reports, each with "Needs Roster", and the summary counts eleven modules; an organization that has not turned them on has them off.
7. Given Learning and Mentoring are on, when the admin turns Roster off and saves, then the save is rejected with "Learning and Mentoring need the roster." beside Roster (`settings-modules/blocked`), the API answers 422 and nothing is stored or deleted.
8. Given the admin turns Learning, Mentoring or Public website on or off and saves, then the change is stored for that organization only, audited, and another organization's configuration is unchanged.

**Traces to:** L1-002

**Acceptance Criteria:**

4. Given Messages is off, when a guardian opens a guardian link, then no messaging options appear and the enrollment and slip pages still work if their modules are on.
5. Given a module is turned off and back on, when its pages load, then every record created before it was turned off is present unchanged.
6. Given Learning is off for Northgate and on for Harbourview, when Lucía (Youth, Northgate) calls `GET /learning/me`, then the API answers 404, while Sofía (Youth, Harbourview) gets 200 with her own record; the same holds for `GET /curriculum` (Learning) and for `GET /mentoring/youth` with Mentoring.

Given Public website is off, or the slug names no organization, or the organization is suspended, when anyone calls `GET /website/{slug}` without signing in, then the API answers 404 with no body, and `/site/{slug}` shows the not-found state without downloading the website library (`website/not-found`); with the module on it answers 200 with the organization's public name only.

4. Given a role change (`change-role`), when saved, then the person's permissions change on their next request and the change is audited.
5. Given a removed staff member (`remove-staff`), when they make any request, then the API answers 401.
6. Given Aisha, a youth worker assigned to tonight's Tutoring night but not to another session tonight, when she opens Today or check-in, then only her session is listed; when she opens or writes to the other session's roster, then the API answers 403 and the page shows that she is not on that session; when Roll Call is off, then the session endpoints answer 404. 7. Given Aisha, a youth worker, when she opens a child or household from her sessions, then the API returns the child's age without the date of birth and no medical fields, with guardian contact kept (`child/forbidden`); when she opens a child or household in none of her sessions, then the API answers 403, the attempt is audited and the page says the child isn't in her sessions (`child/outside-sessions`); Families and child search never include such children. Site leads, directors and admins read every child with the date of birth; another organization's child answers 404; with Roster off, the endpoints answer 404 and the route redirects to Today.
8. Given a youth, mentor or volunteer, when they call any staff endpoint that their role was not granted (families, children, events, programs, Today's summary, search, settings and the rest), then the API answers 403; the session, account, notifications and sign-out endpoints answer them as they do staff.
9. Given Sofía, a youth whose account links to her child record, when she calls `GET /learning/me`, then the API returns only her own record; a youth whose account links to no child gets an empty record, never another child's; staff roles get 403.
10. Given Daniel, a mentor with no youth assigned, when he calls `GET /mentoring/youth`, then the API returns an empty list; youth, volunteers and other staff roles get 403.
11. Given Leo, a volunteer assigned to tonight's Tutoring night only, when he opens Today's sessions or a session roster, then only his assigned session is listed and the other session answers 403, exactly as for a youth worker; he never reads medical fields or dates of birth.
12. Given an admin or program director, when they call `GET /curriculum` with Learning on, then the API answers 200; site leads, youth workers, volunteer coordinators and participant roles get 403.

## L2-010: Roster import from spreadsheet
**Traces to:** L1-004

Staff import households, children, guardians, medical flags and pickups from CSV or XLSX in three steps: upload, map columns, review (`import-roster`).

**Acceptance Criteria:**
1. Given a CSV or XLSX of up to 5,000 rows, when uploaded, then columns are matched automatically and unmatched ones are listed for mapping.
2. Given a row with a duplicate child (same name and date of birth as an existing child), when reviewed, then it is shown as a duplicate and skipped unless the admin chooses to merge.
3. Given a guardian row with no mobile number, when imported, then the household is created with email-only contact and counted in "rows need a look".
4. Given a file that is not a spreadsheet, when uploaded, then the error state explains the accepted formats and nothing is created (`import-roster/error`).
5. Given a successful import of 112 rows, when it completes, then the summary counts match the file and the import is one audit entry listing the file name, row count and importer.
6. Given a mapping without the child's name, the guardian's name, or a guardian phone or email, when it is saved, then each missing field is named and nothing is previewed; given a guardian whose phone is already on file, when imported, then that household is updated instead of duplicated, and a duplicate the admin chose to merge updates the existing child.
7. Given a site lead or volunteer coordinator, when they open the import, then the page says only admins and program directors import rosters and the API answers 403; given another organization's import, then it is not found, and duplicates are matched only within the organization.
8. Given the Roster module is off, when the import page is opened, then Today opens and every `/imports` endpoint answers 404.
