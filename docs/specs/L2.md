# L2 - Detailed Requirements

Each L2 traces to exactly one L1 in `L1.md`. Acceptance criteria are Given/When/Then and are the source for acceptance tests, which must carry a `Traces to: L2-nnn` header comment. Screen ids in parentheses refer to `docs/mocks/`. The cast (Harbourview Youth Collective, Jaylen, Marisol, Tom, the Rivera household) is the shared test fixture.

---

## L2-001: Tenant isolation on every query
**Traces to:** L1-001

Every tenant-owned table carries the organization id; every query, search, export and background job filters by the organization of the signed-in person's active membership, never by a value from the client.

**Acceptance Criteria:**
1. Given two organizations each with a child named "Mateo Rivera", when a staff member of organization A searches "Mateo", then only organization A's child is returned.
2. Given a staff member of organization A, when they request `/children/{id}` for a child of organization B by id, then the API answers 404 and the attempt is written to the audit log.
3. Given a request that carries an organization id in the body or query that differs from the active membership, when it is processed, then the server ignores the client value and uses the membership's organization.
4. Given the seeded demo data, when the integration suite runs, then every feature's cross-tenant test (one per feature) passes.

## L2-002: Active organization and switching
**Traces to:** L1-001

A person can belong to several organizations with a different role in each. One organization is active per session; switching reloads the app for the chosen organization.

**Acceptance Criteria:**
1. Given Priya belongs to Harbourview (admin) and Bayfront (volunteer coordinator), when she signs in, then the top bar shows the org switcher with Harbourview active (`switch-organization`).
2. Given the switcher is open, when she picks Bayfront, then Today reloads with Bayfront's data and her role there, and the active organization is explicit in every subsequent request.
3. Given a person belongs to one organization, when they sign in, then no switcher is shown.
4. Given a person's membership in an organization is removed while they are active in it, when they make the next request, then they are signed out of that organization and returned to their remaining organization or the sign-in page.

## L2-003: Platform administration of organizations
**Traces to:** L1-001

Platform admins list, add, suspend and reinstate organizations; this list is the only screen that spans tenants.

**Acceptance Criteria:**
1. Given a platform admin, when they open `organizations`, then every organization is listed with plan, active children, modules on and status, filterable by plan and status and searchable by name.
2. Given a platform admin adds an organization with a name, a first admin email, a plan and a module preset (`add-organization`), when the form is submitted, then the tenant is created, the admin receives the welcome email and the row shows "Setting up".
3. Given a platform admin suspends an organization with a reason (`suspend-organization`), when confirmed, then its staff and guardian links are refused with a "suspended" message, outbound messages stop, no data is deleted, and reinstating restores access.
4. Given an organization admin who is not a platform admin, when they open `/admin/organizations`, then they get the forbidden state and the API answers 403.

## L2-004: Module configuration per organization
**Traces to:** L1-002

Admins switch modules on or off in `settings-modules` or choose a preset during onboarding (`onboard-modules`). Roster is the data every other module reads; dependencies are declared and enforced.

**Acceptance Criteria:**
1. Given the whole suite is on, when the admin turns off every module except Roll Call and saves, then the configuration is stored with Roster and Roll Call on and the toast confirms 2 modules on.
2. Given Roll Call is off, when the admin turns Pickup on and saves, then the save is rejected with the inline error "Pickup needs Roll Call" and the API answers 422 naming the missing dependency.
3. Given Slips is on, when the admin turns Roster off, then the save is rejected naming every module that needs the roster.
4. Given the admin chooses the "Just check-in" preset in onboarding, when the wizard continues, then Roster, Roll Call and Quick Cards are on and everything else is off.
5. Given a site lead, when they open `/settings/modules`, then they get the forbidden state and the API answers 403.

## L2-005: Modules that are off are unreachable
**Traces to:** L1-002

A module that is off is neither served nor rendered.

**Acceptance Criteria:**
1. Given Reports is off for Harbourview, when any user of Harbourview calls a Reports endpoint, then the API answers 404.
2. Given only Roster and Roll Call are on, when Jaylen opens Today, then the top bar, More menu, phone tab bar and search scopes show only Today, Check-in and Families, and no slip, message, incident or report content is rendered or prefetched (`today/single-module`).
3. Given Slips is off, when a user navigates directly to `/slips`, then they are redirected to Today.
4. Given Messages is off, when a guardian opens a guardian link, then no messaging options appear and the enrollment and slip pages still work if their modules are on.
5. Given a module is turned off and back on, when its pages load, then every record created before it was turned off is present unchanged.

## L2-006: Staff sign-in
**Traces to:** L1-003

Staff sign in with email and password; admins complete MFA; sessions expire after 12 hours of inactivity and can be revoked.

**Acceptance Criteria:**
1. Given valid credentials, when Jaylen signs in (`sign-in`), then he lands on Today within 2 seconds.
2. Given five failed attempts within 15 minutes, when a sixth is made, then the account is locked for 15 minutes and the response does not reveal whether the email exists.
3. Given Tom is an admin with MFA enrolled, when he signs in, then a six-digit code is required (`sign-in/mfa`) and a recovery code can be used once (`recovery-codes`).
4. Given a session older than 12 hours, when the user submits a form, then the session-expired dialog appears, the form content is kept on the device, and after re-authentication the submission completes (`session-expired`).
5. Given the user chooses "Sign out everywhere" (`sign-out-all`), when confirmed, then every other session of that user is invalidated within 60 seconds.

## L2-010: Roster import from spreadsheet
**Traces to:** L1-004

Staff import households, children, guardians, medical flags and pickups from CSV or XLSX in three steps: upload, map columns, review (`import-roster`).

**Acceptance Criteria:**
1. Given a CSV or XLSX of up to 5,000 rows, when uploaded, then columns are matched automatically and unmatched ones are listed for mapping.
2. Given a row with a duplicate child (same name and date of birth as an existing child), when reviewed, then it is shown as a duplicate and skipped unless the admin chooses to merge.

5. Given a successful import of 112 rows, when it completes, then the summary counts match the file and the import is one audit entry listing the file name, row count and importer.

## L2-031: Transport, storage and application security
**Traces to:** L1-016

TLS everywhere, encryption at rest, OWASP Top 10 defences, secrets outside the repository.

**Acceptance Criteria:**
1. Given any HTTP request, when received, then it is redirected to HTTPS and responses carry HSTS, CSP, X-Content-Type-Options and frame-ancestors headers.
2. Given database and backups, then they are encrypted at rest and backups are restorable in a quarterly drill.
3. Given any input field, when a script or SQL fragment is submitted, then it is stored as text, rendered escaped, and never executed (verified by automated OWASP tests on every form).
4. Given an authenticated endpoint, when called without a valid session, then it answers 401; given a CSRF-less cross-site POST, then it is rejected.
5. Given a secret in configuration, then it is never written to logs, error pages or the repository.

## L2-034: Reliability and background jobs
**Traces to:** L1-018

Uptime target, backups and resilient jobs.

**Acceptance Criteria:**
1. Given a month of operation, then measured availability of the API and guardian pages is at least 99.5%.
2. Given the daily backup job, when it runs, then a restorable snapshot exists and a failed backup raises an alert.
3. Given a reminder, alert or export job fails, when retried, then it retries with backoff up to 5 times, never sends a message twice, and surfaces the failure in the admin notification center.
4. Given planned downtime, when the maintenance flag is set, then every page shows the maintenance page with the expected end time and guardian links show the same (`maintenance`).

## L2-035: Accessibility
**Traces to:** L1-019

WCAG 2.2 AA on every screen in both themes.

**Acceptance Criteria:**
1. Given any screen, when axe runs in the Playwright suite, then there are no violations.
2. Given keyboard-only use, when tabbing through a page, a dialog and a toast, then every control is reachable in reading order with a visible focus ring, dialogs trap focus and Escape closes them.
3. Given light and dark themes, then every text and control pair meets 4.5:1 (3:1 for large text and UI components).
4. Given status conveyed by colour (roster stripes, badges, charts), then the same status is conveyed by a word or icon.
5. Given a form error, then it is announced, linked from a summary, and focus moves to the summary.

## L2-036: Responsive layout
**Traces to:** L1-019

Layouts adapt at 360, 576, 768, 992 and 1200 pixel widths and up to 1600 pixels.

**Acceptance Criteria:**
1. Given viewport width under 576px, when a staff page renders, then stats are two per row, lists are single-column, filters stack, the phone tab bar shows and trailing badges wrap under list text.
2. Given width from 768px, then stats are four per row and the top bar shows Today, Check-in, Families, Events and More.
3. Given width from 992px, then Programs, Messages and Reports join the top bar and two-column layouts apply; from 1200px the search field appears.
4. Given width 1600px with the organization switcher present, then the top bar never overflows and the content stays within the 1280px container.
5. Given every section of a staff page, then vertical gaps equal the layout gutter (16px, 24px, 32px by breakpoint) with no component-level outer margins.

## L2-037: Plans and metering
**Traces to:** L1-020

Free up to 50 active children; Standard up to 500 for a flat monthly price; active children and SMS segments are metered.

**Acceptance Criteria:**
1. Given a Free organization with 50 active children, when a 51st child is accepted, then the acceptance is blocked with a message to upgrade and Billing shows the limit (`billing/limit-reached`).
2. Given Billing (`billing`), when opened, then active children and SMS segments for the month are shown against the plan with the next invoice amount.
3. Given a plan change (`change-plan`), when confirmed, then limits apply immediately and the invoice is prorated.
4. Given a failed payment, when the processor reports it, then admins see the banner, service continues for 14 days, and the account is then suspended until paid (`billing/payment-failed`).
5. Given "active child" is defined as enrolled in at least one program this season, then the count matches that definition exactly.

## L2-038: Shell navigation and overflow
**Traces to:** L1-021

The top bar, More menu, phone tab bar and account menu reflect modules, role and organization and never overflow.

**Acceptance Criteria:**
1. Given any width from 360px to 1600px, when the top bar renders, then no item is clipped and the search field keeps at least 9rem of width where shown.
2. Given Incidents and Settings, then they are reachable from More at every width and never rendered inline.
3. Given the More menu (`main-menu`), when opened on a phone, then it is a drawer listing every module that is on plus Settings, Notifications and account, and closes on Escape.
4. Given the account menu (`account-menu`), then it shows the person, their role and organization, theme toggle and sign out.

## L2-039: Global search
**Traces to:** L1-021

Search covers children, households, guardians and events of the active organization, scoped to modules that are on.

**Acceptance Criteria:**

## L2-040: In-app notifications
**Traces to:** L1-021

A notification center lists what needs attention (incidents to review, enrollments to review, bounces, cap warnings) with unread counts.

**Acceptance Criteria:**
1. Given 2 unread notifications, when Today loads, then the bell shows 2 and the dropdown lists them newest first (`bell/unread`).
2. Given a notification is opened, then it is marked read and the count decrements for every device of that person.
3. Given notification preferences (`settings-notifications`), when an admin disables email digests, then no digest is sent to them.
4. Given no notifications, then the empty state is shown (`notifications/empty`).

## L2-041: Observability
**Traces to:** L1-022

Structured logs, metrics and alerts per tenant.

**Acceptance Criteria:**
1. Given any request, then a structured log line records tenant, route, status, duration and a correlation id, and never a child's name or a secret.
2. Given the error rate exceeds 1% over 5 minutes, then an alert is raised to the on-call channel.
3. Given a job queue older than 10 minutes, then an alert is raised.
4. Given request logging, then it sits outside the exception-handling middleware so handled statuses are logged correctly.

## L2-042: Database migrations and seed data
**Traces to:** L1-022

Migrations run only through the CLI; seed data is idempotent and multi-tenant.

**Acceptance Criteria:**
1. Given the API starts against an unmigrated database, then it refuses to serve and logs the pending migration; given the CLI runs migrate, then the schema is current.
2. Given the seed command runs twice, then the second run creates nothing new and changes nothing.
3. Given the seed data, then it contains at least two organizations with distinct modules and plans and the Harbourview cast used by the mocks and tests.
